Personal Productivity Skills Roundup

Meeting notes · inbox · notes · calendar — you can install the plumbing, not the judgment

2026-10-03 · BigCat

Conclusion first for this category: install the plumbing layer, let the official memory layer do its thing, and write the output layer yourself. Below are 11 real, installable or readable entries, each with a link, an install command, and a when-not-to-install. One of them (apple-mcp, 3.1k stars) was archived read-only on 2026-01-01 — that is the hardest honest cost in this issue.

// WHY THIS MATTERS

Meeting notes, inbox, note cleanup, calendar: the four things that look most delegable to AI, and the category where off-the-shelf products help least. The reason is simple. Coding skills have an objective oracle (do the tests pass). Office skills have a deterministic format (is the docx still valid). But what belongs in this meeting's notes is known only to you. So read the table in three layers — pick the wrong layer and you will shop for output skills by star count, then demand that a pipe sound like you.

Entry by entry: what it kills, when to skip it

  • makenotion/claude-code-notion-plugin (491 stars per the repo page, 2026-10) — the only first-party output-layer entry here: it bundles four skills (Knowledge Capture, Meeting Intelligence, Research Documentation, Spec to Implementation) plus ten commands such as /Notion:search, /Notion:create-page and /Notion:tasks:plan. Kills "manually digging through five pages for meeting background." Skip it if your notes do not live in Notion. Get the name right: a separate team-attention/notion-skills-for-claude has 24 stars and was archived on 2025-12-22 — do not copy that one.
  • anthropics/skills · internal-comms (first-party, Apache-2.0) — kills "reinventing the format of every status update, announcement and FAQ." Under examples/ sit four templates: 3p-updates.md (Progress / Plans / Problems), company-newsletter.md, faq-answers.md and general-comms.md; pick the one matching the comms type. This is the structure most worth copying in the whole table: the house style is left as a slot, so swapping the samples makes it yours. Skip it if your company uses none of those formats — then fork the directory shape instead.
  • Claude Code auto memory + CLAUDE.md (first-party, nothing to install) — kills "re-explaining who you are every session." Auto memory writes four kinds of note and records the kind in a type field: user (role and preferences), feedback (your corrections), project (work in flight and decisions), reference (where outside information lives). It is stored under ~/.claude/projects/<project>/memory/, and only the first 200 lines or 25KB load. The docs state plainly that it skips anything derivable from the codebase and anything your CLAUDE.md already says. Turn it off on shared or demo machines — these are machine-local plaintext notes. Use autoMemoryEnabled: false or CLAUDE_CODE_DISABLE_AUTO_MEMORY=1.
  • basicmachines-co/basic-memory (AGPL-3.0; ~4.1k stars per the repo page, 2026-10) — kills "the conclusion you reached in chat evaporating with the window." It settles conversations into markdown with frontmatter, weaving observations and wiki links into a knowledge graph, by default under ~/basic-memory, with a local SQLite index for search. Note the AGPL. Skip it if you already run Obsidian with clear note conventions — two indexes will fight (section 04).
  • @modelcontextprotocol/server-memory (official reference server) — nine tools (create_entities, create_relations, add_observations, search_nodes, read_graph and more), stored in one JSONL file whose path comes from MEMORY_FILE_PATH. Skip it: it calls itself a basic implementation — a single file with no project isolation. Read it as a model, do not run it as your answer.
  • MarkusPfundstein/mcp-obsidian (MIT; ~4.5k stars per the repo page, 2026-10) — kills "browsing the vault by hand and pasting into chat." Seven tools: list_files_in_vault, get_file_contents, search, patch_content, append_content, delete_file and one more. Prerequisite: the community plugin obsidian-local-rest-api inside the vault. Skip it if you use Claude Code and the vault is on the same machine — --add-dir reads the files with one less layer, and hands nothing a delete_file.
  • Doist/todoist-mcp (MIT; 554 stars per the repo page, 2026-10) — kills "reading a paragraph then typing three todos." The valuable part is not the star count, it is the maintainer: Doist maintains this itself, not a hobbyist. Skip it if your tasks are elsewhere, or if a markdown checklist is genuinely all you need.
  • nspady/google-calendar-mcp (MIT; ~1.2k stars per the repo page, 2026-10) — thirteen tools, including get-freebusy, create-events (batch) and manage-accounts (multi-account). Kills "three people comparing free slots." The cost is in its own README: create a Google Cloud project, enable the Calendar API, configure OAuth desktop credentials — and in test mode the token expires after seven days, so you re-authorize weekly. Skip it if you only wanted to see today's meetings.
  • Readwise official MCP — kills "highlights sitting in Readwise and never getting reused." Hosted at https://mcp2.readwise.io/mcp with OAuth; tools include readwise_search_highlights, readwise_list_highlights and readwise_create_highlights. Skip it if you do not use Readwise, or if your reading notes already sync into the vault. Stated plainly: this site's egress policy blocks readwise.io and its docs host, so the command and endpoint above come from two consistent search-engine extracts of Readwise's own docs page. Open that page and check before installing.
  • supermemoryai/apple-mcp (MIT; 3.1k stars) — once covered Messages, Notes, Contacts, Mail, Reminders, Calendar and Maps, and was the most-recommended entry in this category. The repo page now reads: This repository was archived by the owner on Jan 1, 2026. It is now read-only. It is listed not to install but so that "3.1k stars gets abandoned too" enters your shopping criteria — especially since the permissions it wanted were half your digital life.
  • anthropics/skills · skill-creator (first-party) — the real answer for this category: it kills "writing skills by vibes." It pins the process to eleven steps — capture intent, interview for edge cases, draft the SKILL.md, build 2–3 realistic prompts, run with and without the skill in parallel, draft quantitative assertions, grade and aggregate, review with you, iterate, optimize the description for trigger accuracy, package. Its own line is where this issue lands: create skills that can be used a million times, not ones that only fit the examples at hand. Skip it if the thing you want runs exactly once.
Both traps here are about names. (1) "Obsidian MCP" returns at least six same-named repositories, forks included; the one named here is the 4.5k-star MarkusPfundstein/mcp-obsidian. (2) "Official Notion skills" maps to several same-named notion-mcp-server repos plus one archived mirror. Aggregators and search results are for discovering candidates only — verify every name against the GitHub repo tree or the vendor's own page.
// 02

Why these three layers cannot be compared together

Claim: the three layers have completely different acceptance tests, so one set of criteria will pick wrong.
PIPE judge on: coverage · are writes reversible · who maintains it · tool count failure mode: connected, but the model picks the wrong tool — or one delete_file erases your note buy off the shelf? — yes, and you should. No "house style" lives here MEMORY judge on: where it lives · who can read it · does it fight your notes failure mode: two indexes each half full, and you cannot say which to trust buy off the shelf? — start with the built-in one; add more only if short OUTPUT judge on: does it sound like you — there is no second criterion failure mode: grammatically perfect output that you would never have written buy off the shelf? — take its structure only; fill the style slot yourself

Two classic ways to get this wrong: shopping for output skills by star count (you install another company's status-update template, rewrite half of it every time, and would have been better off without it), and demanding that a pipe sound like you (which produces the conclusion "MCP is useless" — it was only ever moving data in).

That is also what SKILLS.md means when it says this category is the one you should build yourself. Not because off-the-shelf quality is bad, but because the output layer's acceptance test lives inside you. Which is why the structure most worth copying is internal-comms: one SKILL.md hanging four sample files — swap the samples, swap the house style.

// 03

A three-minute inspection of the SKILL.md or README

Claim: six criteria are specific to this category, and two of them barely matter elsewhere.
  • 1. Does it read your private context? A "productivity skill" with no data entry point is just a prompt in a different directory — you may as well paste it into the chat. Look for a tool list or API configuration in the README first.
  • 2. Are the writes reversible? This risk is specific to this category: notes and calendars are a destructive write surface. Look for append-only variants and whether deletion requires confirmation. In mcp-obsidian, delete_file and patch_content are the two to watch; for calendars, watch delete-event. If read-only will do, go read-only.
  • 3. Who maintains it? The vendor itself (Doist/todoist-mcp, makenotion/claude-code-notion-plugin) beats a high-star personal repo. While you are there, check the last commit — and whether there is an archive banner at the top of the page. apple-mcp is this criterion's price tag.
  • 4. Is the house style a slot or hard-coded? For output-layer entries this is the only question that matters: is there an examples/ directory under the SKILL.md for you to fill in? internal-comms has four files. Anything with someone else's style baked in has to be rewritten after installing anyway.
  • 5. How much context tax? Count the tools. Thirteen for google-calendar-mcp, seven for mcp-obsidian, nine for the official memory server — turn all three on and thirty tool definitions ride along every turn. Worse is overlap: when two servers can both "search notes," the model has to choose, and one wrong choice costs a full round trip.
  • 6. Privacy radius. What is the largest scope it can reach? The Obsidian pipe gives it one vault; the Apple class gives it mail plus messages plus contacts. Price it at the worst case, not at how you intend to use it.

How to spend the three minutes: one minute on the tool list (that answers 1, 2, 5 and 6 at once), one on the top of the repo page and the commit history (3), one on whether the directory tree has a sample slot (4).

// 04

The honest cost

Claim: the more completely you install this category, the likelier some morning finds half your pipes broken.

1. Abandonment, and of high-star projects

supermemoryai/apple-mcp: 3.1k stars, archived read-only on 2026-01-01. The Notion skills mirror team-attention/notion-skills-for-claude: archived 2025-12-22. A personally maintained integration layer depends on an upstream API not changing, and upstreams never promise that. So star counts are worth less here than in any other category — look at the maintainer.

2. The OAuth tax is paid in real time

google-calendar-mcp wants you to create a Google Cloud project, enable the API and configure OAuth desktop credentials, and its README says outright that test-mode tokens expire after seven days. To save yourself "open the calendar and look," you bought a weekly re-authorization. Do that arithmetic before installing.

3. Two indexes fighting

basic-memory has its own SQLite index and ~/basic-memory directory; your Obsidian vault has its own. Run both and "that decision from last week" exists as half a record on each side. There must be exactly one source of truth: either point basic-memory at the vault directory, or keep only one.

4. The largest cost is not in the tools: the output layer cannot be outsourced. Notice where the official docs draw auto memory's boundary — it records only what you taught it (corrections, preferences, decisions) and explicitly skips what is derivable from the codebase and what your CLAUDE.md already says. The vendor does not decide what is worth remembering for you. So if you expect that installing a skill will make meeting notes come out the way you write them, that expectation is doomed in this category: the ceiling on off-the-shelf value is skipping the steps where you open the app, not having your judgment done for you.
Sources: the archive banner on the apple-mcp repo page · the OAuth and 7-day token notes in the google-calendar-mcp README · Claude Code memory docs, on auto memory's four note kinds and skip rules (all per those pages, 2026-10)

// ONE-PAGE SHOPPING CARD

Install these three first: (1) leave /memory on and write a twenty-line CLAUDE.md — free, first-party, applies to every project, and because auto memory skips what your CLAUDE.md already says, the two complement each other. (2) Install exactly one pipe, the one matching your note system: Obsidian → uvx mcp-obsidian (install obsidian-local-rest-api first); Notion → /plugin install notion-workspace-plugin@notion-plugin-marketplace. (3) anthropics/skills · skill-creator — turn the thing you re-explained three times this week into one skill. That is this category's real answer.

Add as needed: Doist/todoist-mcp (if your tasks really are in Todoist) · the Readwise official MCP (if you have highlights in flight) · basicmachines-co/basic-memory (if you have no note system yet, it can be that system) · anthropics/skills · internal-comms (when you need update or announcement formats — copy the structure, swap the samples).

Explicitly do not install: supermemoryai/apple-mcp (archived) · @modelcontextprotocol/server-memory (it calls itself a basic implementation; read it as a model) · basic-memory alongside Obsidian as two indexes · three servers that can all "search notes" at once · any output-layer template with someone else's house style baked in.

// GLOSSARY

PKM (personal knowledge management)
The pile of private context: notes, highlights, meeting records, calendar.
Pipe layer / memory layer / output layer
This issue's three layers. Pipes move data, memory persists across sessions, output produces the finished thing. Different acceptance tests, so never compare across them.
auto memory
The notes Claude Code writes for itself, in four kinds: user, feedback, project, reference. Machine-local, isolated per repository, and only the first 200 lines or 25KB load.
Sample slot (examples/)
The directory under an output-layer SKILL.md left for you to fill with your own house style. Whether that slot exists decides whether the skill can ever be yours.
Context tax
Every server you connect parks a batch of tool definitions in context, consuming it and raising the odds of picking the wrong tool.
Abandonment
A repository archived read-only. The most common death for a personally maintained integration layer, and unrelated to star count.

// THREE THINGS I CANNOT SETTLE

Why does "build it yourself" hold for this category but not for coding?
The difference is whether an objective oracle exists. Coding criteria live outside the repo — tests pass or they do not, types check or they do not — so a stranger's code-reviewer can be useful to you directly. This category's criteria live in your head: nothing arbitrates "what belongs in this meeting's notes" or "why this highlight matters." The inference is deflating but useful: the ceiling on off-the-shelf value here is skipping the steps where you open the app. If you want judgment done for you, you have to write it — which is why skill-creator sits in the top three of the shopping card.
Auto memory already ships. Do I still need something like basic-memory?
Two questions decide it: where it lives, and whether a human can read it. Auto memory lives under ~/.claude/projects/<project>/memory/, isolated per repository and machine-local (the docs state it is not shared across machines or cloud environments), and it writes only when it judges something worth keeping — it is for the model. basic-memory settles into markdown you can open in Obsidian — it is for humans too. So the question is not which is stronger but whether a person needs to read it. If you already have a vault, the answer is usually: do not add a second store, connect the vault.
Why does everything feel slower after installing a pile of pipes?
Two mechanisms stack. First, tool count: thirteen for calendar, seven for notes, nine for memory — thirty definitions riding along, read every turn. Second, and this is the one that actually costs time, overlap: when mcp-obsidian's search and the memory server's search_nodes are both present, the model must first decide where to look, and one wrong choice burns a whole round trip without telling you it chose wrong. The fix is crude and effective: one path per job; turn the overlapping one off.
