SKILL 25 / ORCHESTRATION · ROUNDUP

编排类 Skills 与 Plugin 榜单

四种原语只有两个轴：谁触发它 · 上下文在哪 — 答不上这两问，装再多也是乱的

2026-09-26 · BigCat

这一类最容易买错：很多人把「多 agent」当成更强的 skill 去装。其实 subagent / hook / slash command / plugin 解决的是四件不搭界的事，选错了不是效果差，是根本不触发。本期先给十条能装的，再给一张两轴坐标把它们各自钉死。

同系列 → Skill 1 编码类 skills 榜单（skill / subagent / MCP 的初步分工在那期）

// WHY THIS MATTERS

别的类别装错了至少还会跑，编排类装错了通常是静悄悄地不生效——「每次提交前跑 lint」写进 CLAUDE.md，模型十次忘三次；需要判断的活写成 hook，它每次都硬邦邦地拦错人。正确用法只有一句：需要判断的交给模型，不需要判断的交给代码，会淹没上下文的挪出去，要给别人用的打成包。本期点名十条真实可装/可读的条目，先给表和命令，判据放后半程。

// 01

先给清单：四种原语 ＋ 六个现成的

论断：前四条是官方机制，不用装、写个文件就有；后六条是别人已经写好的。先认清前四条，后六条才知道该挑哪个。

逐条说人话

  • ① subagent：一个 .claude/agents/*.md，只有 name 和 description 必填，其余如 tools / disallowedTools / model / maxTurns / permissionMode / isolation: worktree 都是可选。全部价值在独立上下文窗口：翻日志、扫全仓这种会冲垮主对话的活扔进去，只把结论拿回来。官方硬数：默认最多 20 个并发（CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS 可调）、最多嵌套 3 层、所有 agent 的 description 加起来超过 15,000 token 会在启动时告警。什么时候别用：结果本来就只有一句话——多开一个上下文纯属交税。
  • ② hook：在 settings 里写一个 hooks 块，生命周期到点就跑你的 shell 命令。这是本类唯一确定性的机制——不靠模型「记得」。官方事件表已铺得很开：PreToolUse / PostToolUse / PostToolUseFailure / PostToolBatch / UserPromptSubmit / PermissionRequest / PermissionDenied / SubagentStart / SubagentStop / Stop / TeammateIdle / TaskCreated / TaskCompleted / InstructionsLoaded / ConfigChange / FileChanged / PreCompact / SessionStart / SessionEnd 等。两条硬规矩：PreToolUse 的 deny 在 bypassPermissions 与 --dangerously-skip-permissions 下依然生效（能收紧、不能放宽）；同一事件的多个 hook 并行跑完才合并，一个 deny 不阻止另一个的副作用。什么时候别用：这件事需要判断——改用 type: "prompt"（单轮）或 type: "agent"（多轮、默认 60 秒超时、最多 50 轮，官方标注实验性）。
  • ③ skill / slash command：现在是同一样东西的两个入口——.claude/skills/<name>/SKILL.md（多文件、热重载），老式 .claude/commands/<name>.md 仍支持但只能单文件。决定「谁能触发」的是两个 frontmatter 字段：disable-model-invocation: true = 只有你能敲（适合 /deploy 这种），user-invocable: false = 只有模型能用。三个被低估的能力：!`命令` 在模型看到内容之前就把 shell 输出灌进去、allowed-tools 在这一轮预批权限、context: fork 把这条命令扔进隔离子会话跑。什么时候别写：只做一次的活。
  • ④ plugin：一个带 .claude-plugin/plugin.json 的目录，把 skills / agents / hooks / MCP servers 打成一个安装单元。它不是第五种能力，是运输箱。官方把代价写得很直白：启用的插件对每个会话都生效，不只是你用到它那次——凡是模型能自己调用的 skill / agent / command，名字与描述每一轮都在 context 里。装前看 /plugin 的 Context cost，装后看 Not used recently。什么时候别打包：只有你一台机器用，直接放 ~/.claude/。
  • ⑤ agent teams（官方明标实验性、默认关闭）：teammate 不是 subagent，而是一个个完整独立的 Claude Code 会话，共享任务清单、通过邮箱文件互发消息，你可以直接跟任何一个对话。官方给的甜区很具体：5 个 teammate 各持一个假设互相证伪，靠辩论破掉单线调查的锚定效应。限制清单同样具体：不能 resume（/resume 恢复不了 in-process teammate）· 不能嵌套（teammate 不能再开 teammate）· 一个会话只能有一个团队 · lead 不能转让 · 关机慢 · 任务状态会滞后。官方建议 3–5 个起步，并明说「三个专注的常常打得过五个散的」。
  • ⑥ security-guidance（官方插件）：本榜最值得先装，也是「hook 编排」最好的活教材——整个插件就是 hooks 堆出来的，三层递进：PostToolUse 抓 Edit/Write 做纯字符串模式匹配（eval(、pickle、dangerouslySetInnerHTML、动了 .github/workflows/ 等，不调模型、零成本）；Stop 在每轮结束后台跑一次 diff 复审（每轮最多 30 个改动文件，最多连开三次）；PostToolUse 过滤 git commit/git push 再跑一次会读上下文的 agentic 复审（每滚动小时最多 20 次）。关键设计：不让写代码的那个实例自己打分，而是另起一个只被告知「找问题」的 Claude。诚实交代：三层都不阻断写入或提交，只把发现塞回去让它改。
  • ⑦ hookify（官方插件）：把「写 hook」这件事本身自动化了。/hookify [描述] 从你的一句话、或直接从这段对话里找出你烦了的行为，生成一条带 YAML frontmatter 的 markdown 规则（event / pattern / action: warn|block），改完不用重启，下一次工具调用就生效；另有 /hookify:list 与 /hookify:configure 管开关。什么时候别装：你已经会手写 hooks 配置——那它只是多一层抽象。
  • ⑧ feature-dev（官方插件）：一条 /feature-dev 命令拉起七阶段流水线，里面挂三个分工明确的 agent——code-explorer（顺执行路径摸清现状）、code-architect（出架构与实现蓝图）、code-reviewer（查 bug 与项目约定）。值得单看的是分工方式：勘探、设计、审查各自独立上下文，谁都不替另一个背书。同市场还有 code-review（PR 级多 agent 评分）与 claude-code-setup（扫一遍你的库，反过来告诉你该配什么自动化）。什么时候别用：改一行的活。
  • ⑨ wshobson/agents（社区 marketplace，MIT）：据其仓库 README，2026-09 自述为 94 个插件 / 202 个 agent / 183 个 skill / 105 个 command，并宣称同时支持 Claude Code、Codex、Cursor、OpenCode、GitHub Copilot 等多个 harness，装法与官方市场一样。用法是「按需取一个插件」，不是整仓装——回看第 ④ 条那句 context 税。
  • ⑩ disler/claude-code-hooks-mastery（社区仓库）：把 13 个 hook 生命周期事件一个一个写成能跑的示例脚本（UV 单文件脚本，hook 之间互相隔离），另附 Builder/Validator 双角色校验与生成 subagent 的 meta-agent。本榜唯一一条「拿来读」而非「拿来装」的：照着改比白手起家快得多。注意：社区仓库跟不上官方事件表，事件名以官方 hooks 文档为准。
另外三条只做提示 · anthropics/claude-code-action（MIT）把这套编排搬进 GitHub Actions，按 @claude 提及 / 明确 prompt / PR 审查自动选模式，最小工作流要 contents: write、pull-requests: write、issues: write 三个权限——给 CI 开写权限之前请先想清楚。davila7/claude-code-templates 用 npx claude-code-templates@latest 挑装 agent / command / hook / MCP 组件。ruvnet/ruflo（原 claude-flow，MIT）是另一个极端——自述 100+ agent、swarm 拓扑与共识机制，它不是「装一个插件」，是换一套 harness；本期不推荐，配置面远大于多数人要解决的问题。
// 02

为什么这十条不能混着比：只有两个轴

论断：横轴是谁按下它（你打字 / 模型自己决定 / 生命周期事件），纵轴是上下文在哪（进主对话 / 隔离 / 根本不进）。四种原语各占一格，没有一格能替另一格。
│ 进主对话上下文 │ 隔离上下文 │ 完全不进上下文 ────────────────────┼───────────────────────┼─────────────────────────┼────────────────────── 你打字触发 │ slash command │ context: fork 的 skill │ —— │ (disable-model- │ /subtask │ │ invocation: true) │ │ ────────────────────┼───────────────────────┼─────────────────────────┼────────────────────── 模型自己决定 │ skill（SKILL.md） │ ① subagent │ —— │ │ ⑤ teammate（独立会话） │ ────────────────────┼───────────────────────┼─────────────────────────┼────────────────────── 生命周期事件触发 │ hook 的 additional- │ agent hook（实验性） │ ② hook（shell 命令） │ Context 回灌那一小段 │ │ ⑥ 就全靠这一格 ────────────────────┴───────────────────────┴─────────────────────────┴────────────────────── ④ plugin 不在这张表里 —— 它是把上面任意几格打包运输的箱子。

最常见的三种错配，全都能从这张表上一眼看出来：

  • 把确定性的事写成指令。「每次提交前跑 lint」写进 CLAUDE.md，等于把右下角那格的活塞进中间那格——它变成一条模型可以忘的建议。它该是一条 PostToolUse hook，或用 ⑦ 一句话生成。
  • 把需要判断的事写成硬 hook。「不许改这个目录」可以硬拦；「这段改动有没有安全问题」不行。后者两条正路：type: "prompt" 的单轮判断，或抄 ⑥——用 Stop hook 在后台另起一个 Claude 复审再回灌。
  • 把 subagent 当 teammate 用。官方对照表：subagent 把结果交回调用者、主 agent 管全部，token 成本低；teammate 之间直接互发消息、自己认领任务，token 成本高（每人一个完整实例）。要讨论和互相质疑才上团队，只要结论就用 subagent。

还有一条容易忽略：开了 ⑤ 之后普通委派也会变。官方原文——启用期间模型自己给 subagent 起了名字就会把它作为 teammate 拉起来，你没要求组队也可能组出团队。不想要就把 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 设回 0。

翻车现场：装了 ⑧ 又装了 ⑨ 里的若干 review 类插件，两边都有叫 reviewer 的 agent。表现不是报错，是模型每次挑一个不同的去调——你以为审查标准在飘，其实是自己装了两把尺子。同一件事只留一个执行者。
// 03

三分钟验货：装之前先答这六问

论断：这一类不看星数，看「它在哪一格」。下面六问答完，选哪个基本就定了。
  1. 这件事需不需要模型判断？ 不需要 → ② hook（或 ⑦ 生成一条）。需要 → ③ skill 或 ① subagent。这一问答错，后面全错。
  2. 结果要不要全文回主上下文？ 不要（日志、全仓搜索、长 diff）→ ① subagent。要 → 直接在主对话里做。
  3. 它是不是每次都必须发生？ 是 → 只有 ② 这一格能保证。写进 CLAUDE.md 的是建议，不是保证。
  4. 要不要模型自己能触发？ 要 → description 要写清「什么时候用我」。不要 → disable-model-invocation: true，别让它自作主张跑 /deploy。
  5. 它常驻多少 context？ 官方口径：每个模型可调用的 skill / agent / command，名字与描述每轮都在。装前看 Context cost，装后看 Not used recently 与 /skill-doctor。① 另有一条：所有 agent description 合计超 15,000 token 会告警。
  6. 要给几个人几台机器用？ 一个人 → 放 ~/.claude/。一个仓库 → .claude/ 提交进去。跨仓库或跨团队 → 才值得做成 ④，配一个 marketplace。
这一节的死线：⑨ 自述 94 个插件、⑩ 覆盖 13 个事件、⑤ 能跑一屋子会话——这些数字都不是选型依据。依据是第 1 问：需不需要判断。答「不需要」却装了一堆 agent，收获的是一堆时灵时不灵的提醒。
// 04

诚实的代价：编排是这一类里最贵的一档

论断：subagent 的代价是 token，hook 的代价是你交出去的执行权，agent team 的代价是协调税——三笔账的结算方式完全不同。

三笔账

  • 常驻 context 税。 天天在付、看不见账单的一笔。从 ⑨ 里装五个插件很轻松，它们的名字和描述从此每轮都在。唯一对策是定期看 Not used recently 然后关掉。
  • hook 以你的身份执行任意代码。 它跑什么都是以你的权限跑。两条实操坑：多个 hook 并行、一个 deny 不阻止另一个的副作用；PreToolUse 的 Bash 匹配是尽力而为的，官方明说「硬性 allow/deny 请用 permission 系统，不要用 hook」。
  • agent team 的 token 线性叠加。 官方原话「显著多于单会话」，且 in-process teammate 的请求落在主对话缓存桶之外，默认 5 分钟 TTL（subagentPromptCacheTtl 可调 1h，但 1 小时缓存写入计费更高）。权限上还有一条：lead 用 --dangerously-skip-permissions 起，所有 teammate 都跟着。

不装任何东西，你还能怎么办

  1. 先写两条 hook，别写 agent。 多数人抱怨的「它老是忘了 X」，都是一条 PostToolUse 能解决的事。不会写就用 ⑦。
  2. 先装 ⑥，零配置且大部分层不花钱。 每次编辑的模式匹配不调模型；花钱的只有每轮结束与每次提交那两层，且都有上限。
  3. 团队之前先试 subagent。 官方自己在 agent teams 文档开头就写了这句：「设团队之前，先看看更轻的方案够不够用。」
那一格永远空着：① 隔离上下文、② 保证每次都跑、⑥ 自动复审、⑤ 让五个实例互相证伪——没有一样能判断「这件事该不该自动化」。⑤ 的限制清单里有一条最说明问题：任务状态会滞后，teammate 有时不把任务标成完成，「活是不是真干完了」至今得你自己看。

// 一页选购卡

先装这三个：① /plugin install security-guidance@claude-plugins-official——零配置、模式匹配层不花钱，而且它本身就是最好的 hook 编排范本。② /plugin install hookify@claude-plugins-official——你的第一条 hook 用它写，改完不重启就生效。③ 一个你自己的 .claude/agents/ 文件（name 与 description 两个字段就够），把最常淹没上下文的那件事挪出去。

按需再加：feature-dev@claude-plugins-official（做整块功能，接受七阶段的开销）· code-review@claude-plugins-official（要 PR 级多 agent 评分）· claude-code-setup@claude-plugins-official（不知道该配什么，让它扫一遍你的库）· wshobson/agents（缺某个特定角色，按插件取，不整仓装）· disler/claude-code-hooks-mastery（要抄 hook 范例，事件名回官方文档核）· anthropics/claude-code-action（要把这套搬进 CI）。

明确别做：把「每次都要做」的事写进 CLAUDE.md 而不是 hook · 把需要判断的事写成硬 deny hook · 同一件事装两个 reviewer · 只有自己一台机器还费劲打成 plugin · 没读限制清单就在生产分支上开 agent teams · 以为 agent 数量越多编排越强——官方原话是「三个专注的常常打得过五个散的」。

// 术语表

subagent
一个 .claude/agents/*.md 定义的助手，跑在自己的上下文窗口里，只把结果交回调用者。默认最多 20 并发、最多嵌套 3 层。
hook
生命周期事件触发的 shell 命令，是这一类里唯一确定性的机制。能收紧权限，不能放宽。
teammate（agent team）
一个完整独立的 Claude Code 会话，与其他 teammate 共享任务清单、直接互发消息。实验性，默认关闭。
plugin
带 .claude-plugin/plugin.json 的目录，把 skills / agents / hooks / MCP servers 打成一个安装单元。它是运输箱，不是第五种能力。
Context cost
/plugin 里官方市场插件详情页显示的常驻上下文估算。装之前就该看的那个数。
disable-model-invocation
skill frontmatter 字段。设为 true 表示只有你能敲，模型不能自己调——给 /deploy 这类命令用。
prompt hook / agent hook
需要判断而非硬规则时用的两种 hook：前者单轮 LLM 评估，后者多轮带工具（默认 60 秒超时、最多 50 轮，官方标注实验性）。
