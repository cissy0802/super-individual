写作类 Skills 榜单：十个真能装的

办公类 skill 有个奢侈品：文件打不开就是错，模型能自己纠。写作类没有——它是整个生态里唯一没有客观 oracle 的一类。本期十个条目全部能点开，同时告诉你这条裂缝把它们撕成了几派。

前置 → Skill 13 办公产出类 Skills 榜单（有 oracle 的那一类长什么样）

// WHY THIS MATTERS

写作类争议最大，原因不复杂：你没法证明一版文字比另一版好。办公类有「文件能不能打开」，编码类有「测试过不过」，写作类只剩「我觉得」。后果是可见的：同一个功能在 GitHub 上有十几份同名实现，星数从 49 到 49.4k 都有。下面十个条目装法全部抄自各自官方页面；第 02 节讲它们分属四种东西，第 03 节给六条不用跑就能验货的判据，第 04 节摊开代价。

逐条说人话

  • ① stop-slop：description 一句话：「Remove AI writing patterns from prose」。它值钱在把要删的东西列成了七类清单：清嗓式开头（「Here's the thing:」）、强调拐杖（「Full stop」「Let that sink in」）、商业黑话（unpack / lean into / deep dive / circle back）、副词（所有 -ly 加 really / just / literally）、元评论（「as we'll see」）、虚假主语（「the decision emerges」）、二元对比（「not because X, but because Y」）。文件里给了改写前后对照。单文件、一条 curl，本榜最轻。
  • ② blader/humanizer：据 GitHub 仓库页，2026-09 为 49.4k 星，是这一类最出名的。25 个模式分五组（把话「摆出来」而不是说出来 / 按规则造节奏 / 充气与借来的权威 / 按规则排版 / 草稿残渣），装完用 /humanizer 调，输出是初稿改写 → 自我批评 → 定稿三段。README 里那句判断值得记住：模型写的是「统计上最可能接下去的东西」，不是有意图的句子。它明写从不编造事实——这是改写类 skill 最该承诺的一条。
  • ③ Aboudjem/humanizer-skill：据 GitHub 仓库页，2026-09 为 245 星，模式数最多（55 个五类），5 种 voice（casual / professional / technical / warm / blunt），但让它独一份的是一个 0-100 的 AI-tell 分数和一个纯 Node、零依赖的本地 metrics CLI：能打分、能比对改写前后。它还带一层保真核对，专查数字、URL、日期、缩写有没有被动过。MIT、无遥测、不出网。
  • ④ humanize-writing：Agensi marketplace 上的同类条目，本系列 Skill 17 单独深挖。这里只提醒一件事：「humanize / humanizer / humanize-writing」不是某个 skill 的名字，是一类东西的通名。能查到的实现就有 blader、Aboudjem、gencharitaci/humanize-skills，以及 skills.sh 上 lguz、jpeggdev、shir-danishyar 等同名条目。装之前必须看清是哪个仓库。
  • ⑤ doc-coauthoring：官方的，全榜唯一一个一行代码、一份 reference 都不带的。它给的是三段流程：先把领域背景「info dump」给模型（团队讨论、架构细节、干系人顾虑），再逐节走「提问 → 头脑风暴 5-20 个选项 → 筛 → 查缺口 → 起草 → 改」，最后拿新读者视角回测（开个 subagent 或另起一个 Claude 实例读，看它哪里读不懂）。它治的不是文笔，是你脑子里的东西没倒干净那个病。
  • ⑥ internal-comms：四份体例文件 examples/3p-updates.md（进展/计划/问题）、company-newsletter.md、faq-answers.md、general-comms.md，用哪种读哪份。它的 description 是第一人称的：「用我公司喜欢的格式写内部沟通」。这句就是使用说明：fork 一份把 examples 换成你公司的，别原样装。
  • ⑦ better-writing：名字容易误会，它其实是 UX 文案——按钮标签、表单报错、占位符、设置项、空状态。12 条规则条条能验收：按钮以动词开头（「保存草稿」不是「好的」）、开关按打开后的状态命名（而不是否定式）、报错文案贴着出错的字段并说清怎么办、一个多步流程只用一套词、链接脱离上下文也要能懂。这是本榜最接近「有客观标准」的写作类条目——界面文案的对错可以对着交互本身判。
  • ⑧ copywriting · copy-editing：来自 coreyhaines31/marketingskills（据 GitHub 仓库页，2026-09 为 50.7k 星、7.7k fork）。前者写落地页/首页文案，后者改已有文案。同仓还有 cold-email、emails、social、marketing-psychology 等 50 个目录。问题也在这儿：npx skills add 一把拖回来 50 份描述，全要挤 Claude Code 那 1,536 字符的预算。要两个就只拿两个。
  • ⑨ seo-audit · programmatic-seo · claude-seo：前两个在 boraoztunc/skills（据 GitHub 仓库页，2026-09 为 347 星），同仓还有 schema-markup、content-strategy。要整套就上 AgriciDaniel/claude-seo（据 GitHub 仓库页，2026-09 为 17.1k 星）：25 个子 skill + 18 个 subagent，覆盖技术 SEO、schema、GEO/AEO、外链与报表；核心零 API key，PageSpeed Insights / Search Console / GA4 是可选增强，DataForSEO 这类要自带账号。它是本榜的异类，第 02 节说为什么。
  • ⑩ 两条流水线：nadiem99/claude-writing-skills（据 GitHub 仓库页，2026-09 为 2 星）把一家 Substack 刊物的编辑流程拆成八段——interview → outline → draft → coach → edit → source-check → top-edit → repurpose，外加 setup / research / status 三个支撑 skill。星数低不代表不能读：它是「把自己的流程写成 skill」最直白的样本，Skill 33 会回到这里。虚构那边是 haowjy/creative-writing-skills（据 GitHub 仓库页，2026-09 为 468 星），目录里 story-memory、character-sim、reader-sim 分管连续性、人物一致性、读者反应——长篇连载的难点是记住三十章前写过什么，不是遣词造句。

// 02

为什么这十个不能混着比：四种东西挤在一张表里

论断：⑤和⑦的差别，比⑦和 stop-slop 的差别还大。一个给你流程，一个给你别人的口味，一个给你一张删除清单。

四种形态

  1. 减法型（①②③④）——输入是已有文本，输出是改写后的文本。共同结构是一张「要删什么」的清单，从 7 类到 55 条不等。这一支是写作类唯一能被机械验收的：想知道有没有生效，数一数 -ly 和破折号就行，③干脆把它做成了分数。
  2. 流程型（⑤⑩）——不告诉你怎么写句子，告诉你先做什么再做什么。⑤的「新读者回测」和⑩的 source-check 是同一个思路：给主观任务硬塞一个外部检查点。
  3. 口味型（⑥⑦⑧）——装的是某个人或某家公司的偏好。⑥是 Anthropic 的内部沟通体例，⑧是一位营销从业者的文案主张，⑦是一套 UI 文案规约。这一支的正确用法是 fork 后替换，不是原样装。（S15 的 brand-guidelines 是同一个坑。）
  4. 技术检查型（⑨）——挂在「写作」名下，其实不属于这一类：schema 过不过校验、页面速度多少分、标题长度超没超，全是客观的。它更像上一期的办公类，判据也该照那套用。
那个陷阱：jooray/humanizer 和 blader/humanizer 同名、同描述、同功能，前者是后者的 fork（多加了斯洛伐克语和捷克语）。据 GitHub 仓库页，2026-09 前者 49 星、后者 49.4k 星。差一千倍，肉眼看不出来。在写作类里搜名字装 skill 是最危险的习惯——这一类同名分叉最多，而且没有任何运行结果能告诉你装错了。

裂缝在哪

四种形态摆开就看清了：越能被机械验收的，争议越小。⑨没人吵，⑦很少吵，①②③吵的是「删多了还是删少了」，⑥⑧吵的是「凭什么按你的口味来」。写作类 skill 的口碑分歧不是质量问题，是这一类的属性——当验收标准是「我觉得」，装机量就只反映谁的营销做得好。

// 03

三分钟验货：六条判据，用上面这十个当量尺

论断：写作类没法靠跑一遍来判断好坏，但打开 SKILL.md 翻三分钟能筛掉八成。上面十个恰好各自示范了一条。
  1. 它要删/要改的东西，有没有列成清单。①列了七类并给出改写前后对照，②列了 25 个，③列了 55 个。只写「让文字更自然流畅」而不给清单的，一律别装——那是把你已经会说的话换个说法还给你。
  2. 有没有一个可复算的信号。③的 0-100 分加本地 CLI 是全榜唯一把主观验收换成数字的。有分数不代表分数对，但它至少让「这次改动是不是真的改善了」变成可以比对的事——这正是 Skill 07 讲 eval 时的同一个要求。
  3. 它承诺不动事实吗。②明写从不编造事实，③专门核对数字、URL、日期、缩写。改写类最贵的 bug 是把「23%」润色成「将近四分之一」——更顺了，但那是另一个数。SKILL.md 里找不到这条承诺的，别让它碰带数据的段落。
  4. 装的是流程还是别人的口味。分辨方法一眼就够：读 description，出现「my company」「我喜欢的格式」这类第一人称的，都是模板（⑥是标准样本）。模板要 fork 后替换，装原件等于把别人的语气挂到你名下。
  5. 星数在这一类最不可信。⑩的非虚构流水线 2 星，内容却比一堆四位数星的「写作助手」实在；jooray/humanizer 和 blader/humanizer 差一千倍星却是同一份东西。没有运行结果背书，星数就是纯粹的传播量。以仓库目录名和 SKILL.md 正文为准。
  6. 它和你已装的那些冲不冲突。①②③④四个抢同一个触发面：模型每次都得挑一个，而它挑哪个你控制不了。同类只留一个——这条在写作类尤其要紧：冲突的表现不是报错，是文风每次都不一样。

// 04

诚实的代价：这类 Skill 的账单长什么样

论断：写作类的 token 税不贵，贵的是它没有收敛条件——装上以后，你分不清是它在帮你，还是你在适应它。

没有 oracle，就没有停下来的理由

办公类 skill 有个奢侈品：文件打不开就是错，模型自己能纠。写作类没有。你会一轮一轮让它再改一版，而每一版都不比上一版更接近任何东西——因为没有「完成」的定义。这是本类最真实的代价，也是 Aboudjem/humanizer-skill 那个 0-100 分即使不完美也值钱的原因：它至少画出了一条停止线。

减法型会删掉你需要的结构

stop-slop 要删的「not X but Y」「所有 -ly 副词」「元评论」，在规范文档、API 文档、合同条款里常常正是精确性本身。「这个参数仅在异步模式下生效」的「仅」不是赘余，删了意思就变。减法型的适用面是散文和营销文案，不是技术写作——触发机制不认这个区别，你得自己认。

其余几笔

  • 描述预算是真的会被挤爆。⑧的 marketingskills 一次装 50 个 skill、⑨的 claude-seo 带 25 个子 skill。Claude Code 把所有描述合并后在 1,536 字符处截断，排在后面的就再也触发不了了——而它不报错，只是安静地不工作。要两个 skill 就只拷两个 SKILL.md。
  • 同名分叉是供应链问题。skill 是别人写的可执行指令，而这一类同名实现多到搜索分不清，「装到了长得像的那一份」是常态而非意外。Skill 30 专讲准入审查，这里先记一条：装之前看仓库是不是 fork、上次提交是什么时候。
  • 「去 AI 味」是场军备竞赛。检测器和改写器互相追，今天有效的句式清单明年未必有效。①②③的清单都是某一时刻的观察快照，不是语言学定律。Skill 17 会把这条坑单独挖开。
  • 口味型会悄悄同化你。装着 copywriting 写三个月落地页，你会开始默认那位作者的主张是通用真理。这类 skill 该当参考读一遍，把认同的那部分改写成你自己的规则，而不是一直挂在触发链上替你做判断。
失败模式：让 blader/humanizer 润色一段季报评述，它把「同比增长 23.4%」改成「增速接近四分之一」、把「截至 2026 年 6 月 30 日」改成「今年年中」。读起来确实不像 AI 写的了，数据也确实不对了。这个 bug 最恶心的地方是：文字更好了、语气更自然了，只有事实错了，而且错得很好听。

// 一页选购卡

先装这三个：stop-slop（curl 单文件到 ~/.claude/skills/stop-slop/，七类清单、最轻）+ Aboudjem/humanizer-skill（npx skills add Aboudjem/humanizer-skill，要一条能复算的停止线时用它，别和 stop-slop 同时挂）+ doc-coauthoring（/plugin install example-skills@anthropic-agent-skills，长文档的难点在想清楚）。

按需再加：internal-comms（fork 一份把 examples/ 四份换成你公司的）· better-writing（做产品界面时，12 条规则直接当验收单）· copywriting / copy-editing（只拷这两个目录，别 npx skills add 整个 marketingskills）· AgriciDaniel/claude-seo（站点真要做 SEO）· nadiem99/claude-writing-skills 或 haowjy/creative-writing-skills（你真在连载）。

明确别装：stop-slop + blader/humanizer + humanize-writing 同时挂（三份描述抢一个触发，文风每次都变）· 只为两页文案拖回 50 个 skill 的 marketingskills · 在技术文档仓库里常开减法型（它删的副词正是你的精确性）· 搜到名字就装（先看是不是 fork——jooray/humanizer 与 blader/humanizer 差一千倍星）。

装完三件事：/skills 看清单只留一个减法型 · /skill-doctor 查 token 成本与调用频次 · 给自己定一条停止线（③的分数，或者「改两版就交」），否则这一类可以无限改下去。

// 术语表

oracle（判对错的依据）
能机械判定输出对不对的东西。办公类是「文件能否打开」，编码类是「测试过不过」。写作类没有——本期所有结论的源头。
AI slop / AI tell（AI 腔 / AI 痕迹）
模型高频产出的可识别句式：清嗓式开头、强行三连、破折号滥用、「not X but Y」。减法型要删的就是它。
false agency（虚假主语）
把动作安给无生命的东西：「决策浮现了」「文化转变了」。真正做这件事的人被藏起来了。
progressive disclosure（渐进披露）
skill 分层加载：name+description 常驻，SKILL.md 触发时才读，附件用到才读。所以稀缺的是描述预算。
fork（分叉）
从别人仓库复制出的副本。写作类同名 fork 极多，装之前看仓库页有没有「forked from」。
