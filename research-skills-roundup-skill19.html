SKILL 19 / RESEARCH · ROUNDUP

研究类 Skills 榜单：十个真能装的

检索层 / 流程层 / 姿态层 各解决什么 · 强研究 skill 都留下可追溯的痕迹

2026-09-20 · BigCat

研究类是最容易被「看起来像研究」骗过去的一类：编号引用、置信度标注、反面证据小节——格式的可信度远高于内容。本期十个条目全部能点开，判据只有一条：它有没有留下让你事后能查的痕迹。

前置 → Skill 9 MCP server 榜单（本期⑥—⑩那一层的通用账本）

// WHY THIS MATTERS

写作类没有 oracle，研究类有半个：引用能不能打开、日期对不对、这句话是不是那篇文章说的，前两件机器就能判。所以这一类真正的分水岭不是「谁写得深」，而是谁在报告之外还留下了一份可复查的账——引用登记表、证据来源标签、被丢弃的源和丢弃理由。下面十个条目装法全抄自各自官方页面；第 02 节讲它们分属三层、不能混着比，第 03 节给六条打开 SKILL.md 三分钟就能验的判据，第 04 节摊开代价。

逐条说人话

  • ① daymade 的三件套（据 GitHub 仓库页，2026-09 为 1.4k 星，MIT）：本榜证据链做得最细的一个。deep-research 的 SKILL.md 把流程钉成 P0–P7，关键在 P3 先建「引用登记表」——去重、编号、记下被丢弃的源和理由，登记表一旦定稿，P5 只许从这张表里引。另有三条硬规矩：每个承重论断必须回头重开原文；绝不臆造 URL，每个定位符都来自真实抓取；证据不足就标 [Unverified] 或干脆略过。同仓 competitors-analysis 要求「仓库层面的结论必须来自本地 clone 的代码，市场层面的说法必须给来源」，fact-checker 只提修改建议、要你点头。缺点是这仓有 59 个目录，整装等于把 59 份描述塞进每一轮。
  • ② 199-biotechnologies/claude-deep-research-skill（据 GitHub 仓库页，2026-09 为 1.0k 星，MIT）：8 段流水线，带回环——Scope → Plan → Retrieve → Triangulate → 提纲精修 → Synthesize → Critique（可回跳）→ Refine → Package。它独一份的地方是两个真跑的校验脚本：validate_report.py（9 项检查）与 verify_citations.py（DOI / URL / 幻觉检测），外加「校验→修→重试，最多 3 轮」的闭环，质量线写死为「至少 10 个来源、每个主要论断 3 个以上」。多源检索要额外装 search-cli 并自带 Brave 之类的 key。
  • ③ Weizhena/Deep-Research-skills（据 GitHub 仓库页，2026-09 为 2.2k 星，MIT）：唯一把人工闸门做成第一阶段的。它先只产出一份大纲——要查哪些条目、每条要采哪些字段——等你增删改完点头，第二阶段才逐条开搜、最后并成一份 markdown。仓里 research-en / research-zh 中英各一套，还有 Codex 版，跨 harness 是它的卖点。代价是装法是手工 cp，还要拷一个 web-search-agent 和 pip install pyyaml。
  • ④ lingzhi227/agent-research-skills（据 GitHub 仓库页，2026-09 为 350 星）：31 个 skill 铺满论文全流程——从 literature-search / novelty-assessment，到 experiment-design / paper-writing-section / related-work-writing，再到 self-review / rebuttal-writing / slide-generation。发现层接 Semantic Scholar、arXiv、OpenAlex、CrossRef 四个 API。它是本榜「域越窄、越该整装」的样本：你真在写论文它就是流水线，你不写就是 31 份白交的描述税。
  • ⑤ discernment-nudge：官方 anthropics/skills 里的（据 GitHub 仓库页，2026-09 该仓 177k 星），全榜最轻，也最容易被低估。它不做研究，它改的是你接收答案的姿态：在给出你可能据以行动的实质答案后，追加 2–3 个贴着刚才那份产出的具体追问，帮你核关键事实、戳假设、看漏了什么上下文；一次对话只做一次。它的 description 花了大半篇幅写什么时候别做——琐碎的 how-to、纯教学解释、只是帮你排版、你要跑的代码、创意写作、以及你已经让它核过了。这句「什么时候别触发」写得比正文还长，本身就是写 skill 的范本。
  • ⑥ openags/paper-search-mcp（据 GitHub 仓库页，2026-09 为 2.7k 星，MIT）：一份东西两种形态——既能当 MCP server，也能当 Claude Code skill 装（paper-search），后者不用碰 MCP 配置。覆盖 arXiv、PubMed、bioRxiv、medRxiv、Semantic Scholar、OpenAlex、CrossRef、Europe PMC、dblp、Zenodo、HAL、SSRN 等二十余个源，策略是「免费优先」：多数源不用 key，Semantic Scholar / CORE / Unpaywall 等配了更稳。
  • ⑦ blazickjp/arxiv-mcp-server（据 GitHub 仓库页，2026-09 为 3.2k 星，Apache-2.0）：19 个工具，本地跑。它值钱在「痕迹」是物理的——论文下到 ~/.arxiv-mcp-server/papers 留在盘上，能按节读 LaTeX 原文而不是读摘要转述，能从 arXiv 元数据直接出 BibTeX，还能挂主题监听。核心功能不需要外部检索服务；Semantic Scholar 的 key 只是让引文图查得更稳。
  • ⑧ exa-labs/exa-mcp-server（据 GitHub 仓库页，2026-09 为 5.0k 星，MIT）：默认只暴露 web_search_exa 和 web_fetch_exa 两个工具，agent_run 等要显式开。托管端点可匿名用（有速率限制），配 key 或走 OAuth 才上量。在「工具位预算」这件事上它是本榜最克制的——对照⑨看。
  • ⑨ firecrawl/firecrawl-mcp-server（据 GitHub 仓库页，2026-09 为 7.5k 星，MIT；组织早先叫 mendableai）：本榜星最多，功能也最杂——默认 25 个工具：scrape / map / crawl / search，一组 firecrawl_research_* 论文工具，外加八个 firecrawl_monitor_*。竞品情报那条线真正落到工具上的就是这八个：建监听、跑检查、看某个站点的哪一页变了。云端要 key，也能 FIRECRAWL_API_URL 指向自托管。
  • ⑩ tavily-ai/tavily-mcp（据 GitHub 仓库页，2026-09 为 2.4k 星，MIT）：四个工具 tavily-search / tavily-extract / tavily-map / tavily-crawl，工具数介于⑧和⑨之间，是「要搜也要整站遍历、但不想上 25 个工具」时的中间档。必须要 key。

// 02

为什么这十个不能混着比：它们是三层，不是一排

论断：检索层决定你能拿到什么，流程层决定你留下什么痕迹，姿态层决定你怎么接收结论。三者是互补关系，可绝大多数人只装了中间那层。
姿态层 ⑤ discernment-nudge → 答完之后逼你回头看 ↑ 流程层 ①②③④ deep-research 类 → 拆题 · 派活 · 登记引用 · 反查 · 成稿 ↑ （它自己不会上网） 检索层 ⑥⑦⑧⑨⑩ MCP servers → 网页 / 论文 / 整站 的字节从这儿来

最常见的一种装法是错的：同时装①和②。两个都往 ~/.claude/skills/deep-research 放，名字也撞；就算你改了目录名，两份描述会抢同一个触发词（「research this topic」「写一份报告」），每次走哪套流程随机。流程层挑一个，这是硬规矩。

反过来更常见：流程层装得很讲究，检索层一个没装。于是①那套「重开原文核对承重论断」落到默认网页搜索上——能搜到的还是那些 SEO 聚合页。流程再严，也严不过它手里那只眼睛。要查论文就上⑥⑦，要盯竞品站点就上⑨的 firecrawl_monitor_*，要的只是「搜得准、少占工具位」就⑧。

④是第三种东西：它不是通用研究，是学科流水线。拿它写市场调研会很别扭——rebuttal-writing、latex-formatting 这些在你的场景里永远不触发，却每轮都在交描述税。判断很简单：你产出的东西带不带参考文献表？带就装，不带就别装。

翻车现场：装了①+②+③，结果三个流程层轮流抢同一个触发词；检索层一个没有。表现是「每次出来的报告格式都不一样，但引用永远是那几个聚合站」——这不是模型不行，是你给它的三套流程都指向同一双眼睛。
// 03

三分钟验货：打开 SKILL.md 看这六条

论断：研究类比写作类幸运——它有半个 oracle。引用能不能打开、日期对不对，机器就能判。所以判据全部围绕一件事：这东西有没有留下让你事后能查的账。
  1. 有没有一份独立于正文的引用账本？ ①在 P3 建登记表、编号去重、记录被丢弃的源和丢弃理由，且登记表定稿后正文只许从表里引。没有这层的，引用就是正文的装饰品——你没法查它引了什么、又扔了什么。
  2. 不确定性有没有出口？ 找 [Unverified]、confidence marker、「查不到就写查不到」这类词。一个不允许输出「不知道」的研究 skill，一定会把不确定编成确定——因为你只给了它一个出口。
  3. 有没有日期口径？ ①把 AS_OF 定在 P0，所有时效性论断都要挂来源日期。没有这条，去年的数字和今年的会被平等地写进同一句话。
  4. 有没有机器能跑的校验？ ②的 verify_citations.py 查 DOI / URL 是否存在，validate_report.py 跑 9 项检查。这是本类里唯一不用读内容就能判错的东西。但注意它的边界，见第 04 节。
  5. 人能在哪一步介入？ ③把大纲批准做成阻塞式的第一阶段。研究最贵的错是方向错，而方向错只在开头几分钟里便宜。只在最后让你「审阅报告」的，等于没有闸门。
  6. 它假设你手上有什么工具？ 这条最容易漏。翻 SKILL.md 里提到的检索能力：是自带脚本（④接四个学术 API、②要 search-cli）、还是默认你已经装了某个 MCP？假设落空的时候它不会报错，只会安静地降级。

六条里只要有三条答不上来，这个 skill 给你的就是研究的版式，不是研究。

// 04

诚实的代价：这一类贵在哪、骗你在哪

论断：研究类是最贵的一类 skill，而且贵得不显眼——token 花在你看不见的 subagent 里，信任成本花在「它看起来查得很细」这一念之差上。

钱

Anthropic 自己公开过账：据其工程博客《How we built our multi-agent research system》，2025-06，Research 走的是 orchestrator-worker——主 agent 拆题、并行开若干带独立上下文的 subagent、最后合并并单独跑一遍引用。收益是 Opus 4 主 + Sonnet 4 子的组合在内部研究评测上比单个 Opus 4 高 90.2%；代价是大约 15 倍于一次普通对话的 token，而且这篇明说了它不适合紧耦合的任务（比如写代码）。①②那种「主 agent + subagents」的流程层，花的就是这笔钱。一份深研报告的成本，你该按一次编译而不是一次提问来预期。

工具位

⑨默认 25 个工具定义，⑧默认 2 个。这些定义每一轮都在上下文里，不管你用不用。装两个检索 MCP 之前先数工具数——同理①那仓 59 个目录、④那 31 个 skill，整装的代价是每轮都交的描述税。装完跑 /skill-doctor，它会给出每个 skill 的 context 成本和调用频次。

骗你的地方

引用核验 ≠ 事实核验。 verify_citations.py 能确认这个 DOI 存在、这个 URL 打得开，但它不检查「这句话是不是那篇文章说的」。一条链接真实、编号规整、却支撑不住它挂着的那句论断——这是研究类最高频的假阳性，而它恰好能通过所有自动校验。

第二个陷阱是格式的可信度高于内容：编号引用、置信度标注、「反面证据」小节，都是取信于人的视觉信号。一个只会套版式、不会真的重开原文的 skill，产出和真研究在屏幕上长得一模一样。第 03 节那六条判据，本质上就是在问「这份版式背后有没有账」。

第三，这类 skill 绝大多数默认吃公开网页，二手聚合站会被当成来源——本站 Skill 21 会单独拆这件事。

// 一页选购卡

先装这三个：daymade/claude-code-skills 的 deep-research（只拷这一个目录，别整装 59 个；要的是它的 P3 引用登记表和 [Unverified] 出口）+ exa-mcp-server（claude plugin install exa@claude-plugins-official，默认只占 2 个工具位，给流程层配一只像样的眼睛）+ discernment-nudge（/plugin install discernment-nudge@anthropic-agent-skills，官方，最轻，一次对话只追问一次）。

按需再加：openags/paper-search-mcp（查论文，多数源免 key）· blazickjp/arxiv-mcp-server（要 BibTeX、要论文落盘留档）· Weizhena/Deep-Research-skills（想在大纲处卡一道人工闸门时换掉上面的流程层）· 199-biotechnologies/claude-deep-research-skill（想要 verify_citations.py 那种能跑的校验）· firecrawl-mcp-server 的 firecrawl_monitor_*（真的在盯竞品站点）· tavily-mcp（要整站 map/crawl 但不想上 25 个工具）· lingzhi227/agent-research-skills（你真在写论文）。

明确别装：①和②同时挂（同名目录 ~/.claude/skills/deep-research，且抢同一个触发词）· 装了流程层却一个检索 MCP 都没有（严格的流程配默认的眼睛）· 为一次搜索上 firecrawl-mcp 的 25 个工具 · 不写论文却整装 agent-research-skills 的 31 个 skill。

装完三件事：/skill-doctor 数工具位与 context 成本 · 拿第 03 节六条把手里这个流程层过一遍 · 给自己留一条底线——凡是你要拿去做决定的数字，亲手点开那条引用。

// 术语表

citation registry（引用登记表）
独立于正文的一张源清单：去重、编号、记下丢弃的源与理由，冻结后正文只许从表里引。本期第一判据。
evidence family（证据家族）
同一份财报／同一项研究衍生出的多篇报道算一个源。不合并就会把一个来源数成五个，制造出虚假的相互印证。
AS_OF（数据口径日期）
研究开始时钉死的「截至日」。所有时效性论断都要挂来源日期，否则去年的数字会被当成今年的。
orchestrator-worker（主从编排）
主 agent 拆题并派给若干带独立上下文的 subagent，最后合并。深度研究的常见架构，也是 15 倍 token 的来源。
工具位预算
每个 MCP server 的工具定义都常驻上下文。exa 默认 2 个、firecrawl 默认 25 个——这是装检索层时真正要比的数。
