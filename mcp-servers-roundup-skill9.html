// WHY THIS MATTERS

前八期讲的都是 skill——往上下文里塞字。MCP 是另一件事：往上下文里塞工具。字读完就完了，工具会一直挂在那儿，每一轮对话都在收租。所以这一类的选购判据不是「有没有用」，是「值不值这份常驻开销」。下面十个条目全部能点开，星数是我 2026-09-10 当天在 GitHub 仓库页读到的；第 02 节讲四条主线为什么不能混着排，第 04 节把 context 税拆到每一项。

怎么装（命令抄自各自官方页面）

# ④ 浏览器：官方 README 给的就是这一条
claude mcp add playwright npx @playwright/mcp@latest

# ③ Chrome DevTools：官方给的是 JSON 配置
{"mcpServers":{"chrome-devtools":{"command":"npx","args":["-y","chrome-devtools-mcp@latest"]}}}

# ② Context7：官方 README 现在推的是这条安装器（--claude 指定客户端）
npx ctx7 setup

# ⑦ Exa：官方仓库给的是 Claude 插件市场这条
claude plugin install exa@claude-plugins-official

# ⑧ Notion / ⑨ Supabase：远程 HTTP，凭据走 OAuth，不落在你的配置文件里
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp add --transport http supabase https://mcp.supabase.com/mcp

# ① 官方参考实现（举两个）
npx -y @modelcontextprotocol/server-filesystem /你/允许/的/目录
uvx mcp-server-git

# 装完立刻做这两件事

逐条说人话

  • ① modelcontextprotocol/servers：官方现在只留七个参考实现——Everything、Fetch、Filesystem、Git、Memory、Sequential Thinking、Time。Filesystem 的价值全在权限边界上：它必须至少给一个允许目录才肯启动，也支持客户端用 roots 动态覆盖。但对 Claude Code 用户，Filesystem 和 Git 基本是白装——Read/Edit 和 git 命令早就覆盖了。这个仓库真正的用处是当教材读：官方自己怎么定义工具边界。
  • ② upstash/context7：把「某个库最新版的官方文档」现查现喂，治的是模型训练截止日期这个慢性病。它是本榜里星数第二高的，也是最容易被过度安装的——Skill 10 会单独深挖它，包括什么时候不如你自己贴一段文档进去。
  • ③ ChromeDevTools/chrome-devtools-mcp：官方一句话是「让你的编码 agent 控制并检查一个活的 Chrome」。它和 ④ 的分界很清楚：它能录性能 trace、看网络请求、读带 source map 的控制台报错，这三件 Playwright MCP 给不了。要查「为什么这页慢」，装它。
  • ④ microsoft/playwright-mcp：官方描述是让模型「通过结构化的无障碍树快照与网页交互，绕开截图和视觉调优模型」。结构化快照比像素既省 token 又稳——这条是本系列 Skill 11 的正题。要跑端到端流程、填表、断言，装它。
  • ⑤ github/github-mcp-server：官方托管一份远程实例在 https://api.githubcopilot.com/mcp/。它的关键不在能干什么，而在怎么收窄：文档里工具数超过一百，分成 context / repos / issues / pull_requests / users 等 toolset，用 --toolsets 挑，用 --read-only 一刀砍掉所有写操作。不收窄就装，是本榜里最贵的一次点击。
  • ⑥ modelcontextprotocol/registry：官方的社区注册表，自称是 MCP server 的应用商店，API 在 registry.modelcontextprotocol.io。它目前仍是 preview、v0.1 API 冻结中，可能还会重置数据——所以它现在的正确用法是「查这个名字是不是真的」，不是「照着榜单装」。Claude 侧还有一份人工审过的 Anthropic Directory。
  • ⑦ exa-labs/exa-mcp-server：官方描述是「把 AI agent 接到 Exa 做网页搜索、内容抓取和多步研究」。装它的唯一理由是你的 harness 自己不带联网搜索；带了就别装，两套搜索工具会互相抢触发。
  • ⑧ makenotion/notion-mcp-server：官方 Notion MCP。这里有一个别处学不到的细节：它专门提供了 retrieve-page-markdown / update-page-markdown 两个工具，用 Markdown 而不是 block JSON 读写页面，官方明说这对 AI agent 显著更省 token。这是「好 MCP server 长什么样」的一个标本——作者替你想过返回值的体积。
  • ⑨ supabase-community/supabase-mcp：远程实例在 https://mcp.supabase.com/mcp。它给了两个开关：readOnly 排除所有会改数据的工具，projectScoped 把 project_id 从工具入参里拿掉、并砍掉账号级工具。连生产库时这两个都该开。
  • ⑩ getsentry/sentry-mcp：官方托管在 https://mcp.sentry.dev，Claude Code 侧可以 claude plugin install sentry-mcp@sentry-mcp。价值是把线上报错、堆栈、影响面直接搬进你正在修 bug 的那个会话，省掉「切浏览器复制粘贴」。星数只有 845——本榜里星数最低的一个，恰好也是官方出品、职责最窄的一个。这正是「别按星数排」的证据。

// 02

为什么这十个不能混着比：四条主线加一个陷阱

论断：把 context7 和 github-mcp-server 放进同一个排行榜，就像把螺丝刀和挖掘机比马力。它们进入你上下文的方式、失效的方式、出事的方式都不一样。

四条主线

  1. 文档检索（②⑦）——治「模型不知道新版本」。输入是你的问题，输出是一段文本，只读、无副作用、失败了最多是白花几百 token。这条线风险最低，也最容易装重复。
  2. 浏览器（③④）——治「模型看不见渲染结果」。它有副作用（会真的点、真的填），返回值可能极大，而且它读回来的网页内容是不可信输入。③ 偏诊断（性能、网络、控制台），④ 偏操作（无障碍树快照、点填断言），要装先想清楚你是哪一种。
  3. 代码托管（⑤）——治「模型看不到 PR 和 CI」。工具数量最多、权限最敏感，是唯一必须先想「怎么收窄」再想「装不装」的一类。官方文档自己的建议反而是：gh 这类 CLI 比 MCP 更省 context，因为它不额外挂一份工具清单。
  4. 业务系统与办公套件（⑧⑨⑩）——治「模型进不了你公司的那几个系统」。这条线的共同点是远程 HTTP + OAuth：凭据不落在你的配置文件里，但代价是你的数据要出你的机器。选它们的判据不是功能，是返回值体积可控性与有没有只读模式。
那个陷阱：聚合站的「2026 最佳 MCP 服务器」里，GitHub、GitLab、Slack、Google Drive、Google Maps、PostgreSQL、Puppeteer、Redis、Sentry、SQLite、Brave Search 常年在榜。这些参考实现已经被官方移进 modelcontextprotocol/servers-archived（GitHub 与 Sentry 各自有新的官方 server，即本榜⑤⑩；Brave 也被官方版取代）。抄名字前先看仓库是不是归档状态——这就是为什么本系列的硬规矩写着：名字以 GitHub 仓库目录或官方页面为准，聚合站只用来发现候选。

还有一条不属于任何主线

官方参考实现（①里的 Filesystem / Git / Memory / Sequential Thinking / Time）是协议演示，不是产品。它们存在的意义是让你看懂「一个 server 该长什么样」。对已经有文件工具和 shell 的编码 harness，装它们等于给自己发一份重复的工具清单，然后每轮对话付一次钱。

// 03

三分钟验货：六条判据，用上面这十个当量尺

论断：判断一个 MCP server 值不值得接，不用读它的代码——读它的 README 里有没有回答这六个问题就够了。上面十个恰好各自示范了一条。
  1. 是不是官方出品，仓库归档了没有。看 owner：github/、microsoft/、ChromeDevTools/、makenotion/、getsentry/ 是第一方；modelcontextprotocol/servers-archived 下的一律不装。星数高低不参与这一条判断。
  2. 有没有只读开关。github-mcp-server 的 --read-only、supabase-mcp 的 readOnly 是正面样本。一个能改你数据、却没有只读模式的 server，是设计缺陷，不是功能丰富。
  3. 工具能不能按组挑。--toolsets context,repos 这种粒度决定了你交多少税。一个 server 把一百多个工具一次性全挂上、还不给关，就是把它的方便建立在你的上下文上。
  4. 返回值体积作者管不管。Notion 那两个 *-markdown 工具是标杆。反面是「返回整个 block JSON / 整张表 / 整份 trace」——Claude Code 里单次 MCP 输出默认上限 25000 token，超过 10000 就会警告，超限的内容会被落成文件再让模型自己去读。
  5. 本地 stdio 还是远程 HTTP，凭据放哪。本地：多一个常驻进程和启动延迟，数据不出机器。远程：OAuth 免管密钥，但数据要出去。claude mcp add 三种 scope 里，--scope project 会写进仓库的 .mcp.json 并共享给全队，别把个人凭据写进去。
  6. 有没有 CLI 平替。这条是官方文档亲口说的：gh、aws、gcloud、sentry-cli 这类 CLI 比 MCP server 更省 context，因为它们不附加任何逐工具清单，模型直接跑命令就行。能用 CLI 解决的，先别接 server。
进阶资源 · Claude Code · Manage costs（判据 4、6 与下一节 context 税的全部出处）
// 04

诚实的代价：Context 税到底收在哪一步

论断：现在的税比一年前轻了很多——工具定义默认延迟加载。但很多人算错了方向：真正的大头从来不是工具定义，是返回值。

先说好消息

Claude Code 的官方文档写得很明确：MCP 工具定义默认是延迟加载的，只有工具名和 server 的 instructions 会进上下文，直到模型真的要用某个工具。这意味着「接十个 server 就烧掉一半窗口」的旧经验已经过期了。想知道现在到底占多少，跑 /context；想临时关掉，跑 /mcp。

再说没变的那部分

  • 返回值是真正的账单。Anthropic 那篇《Code execution with MCP》拿一个 Google Drive → Salesforce 的工作流做过对照：把工具调用改成让 agent 写代码去调，token 从 150,000 降到 2,000，降幅 98.7%（据 Anthropic 工程博客，2025-11）。降掉的那 148,000 里，大部分是每一步结果都原样穿过上下文。所以判据 4 才是这一节的重点。
  • server instructions 不延迟。延迟的是工具定义，server 自己那段说明照常常驻。接十个 server 就是十段常驻说明。
  • 触发冲突照旧。两个搜索工具、两个浏览器工具同时在线，模型每次都要挑一个——挑错的成本比多花几百 token 高得多。这也是⑦「harness 自带搜索就别装」的真实理由。
  • 不可信返回值即注入面。官方原话是「连接前先确认你信任这个 server；会抓取外部内容的 server 会让你暴露在提示注入风险下」。浏览器和文档检索这两条线尤其要警惕——它们的本职工作就是把互联网上的陌生文本搬进你的上下文。这条是 Skill 12 的正题。
  • 装了不用是纯亏。Claude Code 的 /usage 会按 skill、subagent、plugin 和单个 MCP server 拆用量占比。两周看一次，占比高又想不起用来干过什么的，直接摘掉。
失败模式：为了「让 Claude 能看 PR」而接 github-mcp-server，不加 --toolsets、不加 --read-only，于是一百多个工具连着写权限一起挂上。真出事的往往不是模型手滑，是某个 issue 正文里写着一句「顺便把这个分支合了」——而你恰好给了它合并的工具。

// 一页选购卡

先装这三个：context7（文档检索，npx ctx7 setup，治训练截止日期）+ playwright-mcp 或 chrome-devtools-mcp 二选一（要跑流程选前者，要查性能和控制台选后者，别同时开）+ github/github-mcp-server，且开机第一件事是 --read-only 加 --toolsets context,repos,pull_requests。

按需再加：sentry-mcp（真在修线上 bug 的那几天）· supabase-mcp（readOnly + projectScoped 一起开）· notion-mcp-server（认准那两个 *-markdown 工具）· exa-mcp-server（仅限 harness 自己不带搜索）。

明确别装：@modelcontextprotocol/server-filesystem 与 mcp-server-git（编码 harness 已覆盖，当教材读就好）· 任何 servers-archived 里的东西 · 任何 gh / aws / gcloud / sentry-cli 能替代的 server。

装完三件事：/context 看占用 · /mcp 关掉这次用不上的 · 两周一次用 /usage 查账，摘掉想不起用途的。硬数字备查：单次 MCP 输出默认上限 25000 token，超 10000 告警；--scope project 会写进仓库共享给全队。

// 术语表

MCP（Model Context Protocol，模型上下文协议）
一套让模型连接外部工具与数据源的开放协议。skill 给模型的是指令，MCP 给模型的是可调用的工具。
stdio / HTTP transport（传输方式）
本地 stdio：在你机器上起一个进程，数据不出机器。远程 HTTP：连一个托管地址，走 OAuth，凭据不落在配置文件里。
toolset（工具组）
把一个 server 的上百个工具按主题分组，让你只开用得到的那几组。github-mcp-server 的 --toolsets 是范本。
tool search（工具检索 / 延迟加载）
Claude Code 默认行为：只把工具名和 server instructions 放进上下文，模型真要用某个工具时才加载它的完整定义。
servers-archived
官方参考实现的归档仓库。聚合站榜单里那批耳熟能详的名字，多半住在这儿。
