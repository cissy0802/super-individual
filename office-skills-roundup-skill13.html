办公产出类 Skills 榜单：十个真能装的

这份榜单第一句就得泼盆冷水：你在 claude.ai 上用得很爽的那四个文档 skill，在 Claude Code 里装不到——官方文档白纸黑字写着不提供。你能装的是 GitHub 上那份同名但另一码事的开源版。

前置 → Skill 01 AI 编码 Skills 榜单（三种形态别混着比）

// WHY THIS MATTERS

前十二期讲的东西，收益都要过几天才看得出来。办公产出类不一样：它交付的是一个文件，能不能打开是客观的、当场的、不用你信任何人。这也是它成为整个 skill 生态里最容易变现的一类的原因——有 oracle，模型就能自己纠错。下面十个条目全部能点开，装法抄自各自官方页面；第 02 节讲这十个为什么分属三种完全不同的东西，第 04 节把代价摊开。本表不按星数排——办公类的头部就那么几个，星数排出来只会让你误以为最热的就该先装。

怎么装（命令抄自各自官方页面）

# ①②③④ Claude Code：一条命令拿到四件套（marketplace 名是 anthropic-agent-skills）
/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills

# ⑥⑦⑧⑨ 在另一个插件里，一起装（还捎带 skill-creator、mcp-builder 等）
/plugin install example-skills@anthropic-agent-skills

# ⑤ Claude API：不是「装」，是在 container 里点名，且必须开 code execution 工具
container: { skills: [ { type: "anthropic", skill_id: "pptx" } ] }
# skill_id 只有四个：pptx / xlsx / docx / pdf

# ⑩ markitdown：读的那一半，pip 装
pip install 'markitdown[all]'
# 只要三种格式就别装全：
pip install 'markitdown[pdf, docx, pptx]'
# 它还有个 MCP 版，只暴露一个工具 convert_to_markdown(uri)
pip install markitdown-mcp

# 装完立刻做这两件事
/skills          # 看清单，关掉这次用不上的
/skill-doctor    # 看每个 skill 的 token 成本与调用频次（v2.1.252+）

逐条说人话

  • ① docx：它不是「调个库生成 Word」。SKILL.md 第一层是决策树——新建就写 Node 脚本用 docx 包；编辑就解包改 word/document.xml 再重打包；只读就一条 pandoc -t markdown。真正值钱的是 scripts/merge_runs.py：Word 会把一句话切成一串 run，不先合并，查找替换十次有九次替换不到。另有 accept_changes.py 处理追踪修订、comment.py 处理批注（要同时改六个互相链接的文件）。
  • ② pptx：新建走 pptxgenjs，编辑走解包改 XML，读用 markitdown 或 scripts/thumbnail.py 出缩略图网格。它的坑写得比谁都实在：先设 layout 再加页（默认 10×5.625 英寸不是 13.3）、十六进制色不带 #、阴影配置对象不能跨调用复用。生成完必跑 scripts/office/validate.py，查 schema、关系、图表。
  • ③ xlsx：openpyxl 写公式、pandas 灌数据、markitdown 快速看一眼，最关键的是写完公式跑 scripts/recalc.py——openpyxl 只写公式不算值，不重算你交出去的是一张全是 = 号没有数的表。它老实交代的限制值得抄下来：不支持会溢出的数组函数（XLOOKUP / FILTER / UNIQUE / SEQUENCE，改用 INDEX+MATCH）、2007 年后的新函数要带 _xlfn. 前缀、data_only=True 读的是缓存值且一存盘就把公式毁了、外部链接重存会被剥掉。
  • ④ pdf：覆盖面最宽的一个——合并拆分转页用 pypdf 或 qpdf，抽文字抽表格用 pdfplumber，新建用 reportlab，扫描件 OCR 用 pytesseract+pdf2image，表单填写另开一份 FORMS.md。它是四件套里唯一不靠 OOXML 解包的，所以也是唯一不依赖 LibreOffice 的。
  • ⑤ 预置四件套：官方托管版，在 claude.ai 和 API 上开箱即用，API 侧按 skill_id 点名。两条硬限制要记住：必须搭 code execution 工具（skill 就跑在它的容器里），而那个容器没有网络、也不能运行时装包。官方文档明说：Claude Code 不提供预置文档 skill。所以「我在网页版用得好好的，为什么终端里没有」的答案就在这——你要的是①②③④。
  • ⑥ doc-coauthoring：整个榜里唯一一个脚本都不带的。它给的是流程：先把领域知识掏给模型，再一节一节写，最后拿「新读者」视角回测盲区。它和①的关系是内容 vs 容器——先用它把话想清楚，再用 docx 装进 Word 里。
  • ⑦ internal-comms：四份体例文件 3p-updates.md（进展/计划/问题）、company-newsletter.md、faq-answers.md、general-comms.md，用哪种读哪份。它的 description 写得极其个人化——「帮我用我公司喜欢的格式写内部沟通」。这句是个信号：这类 skill 的正确用法是 fork 一份塞自己公司的体例，不是原样装。
  • ⑧ theme-factory：十套预设主题（Ocean Depths、Modern Minimalist、Midnight Galaxy 等），带一份 theme-showcase.pdf 让你先看再选，也能现生成新主题。它是「样式与内容分离」的干净样本：主题只是一堆色值与字体配对，套在幻灯片、文档、落地页上都行。
  • ⑨ brand-guidelines：注意它装的是 Anthropic 自己的品牌——主色 #141413、标题 Poppins、正文 Lora，还带按背景自动选色和字体回退（Arial / Georgia）。照装等于把别人家的门头挂到你店上；它的正确用途是当模板，把里面的色卡换成你的。本系列 Skill 15 单独深挖这一类。
  • ⑩ markitdown：官方描述是「把文件和办公文档转成 Markdown 的 Python 工具」，PDF / Word / Excel / PPT / 图片（EXIF + OCR）/ 音频（转写）/ HTML / CSV / JSON / XML / ZIP / EPub 都吃。它不是 skill，是四件套里被反复调用的那个底层工具——②③的「读」这一步直接就是它。单装也完全成立，且是本榜里唯一在任何环境都能用的。

// 02

为什么这十个不能混着比：三种东西挤在一张表里

论断：①和⑥的差别，比①和 markitdown 的差别还大。一个给模型脚本，一个给模型流程，一个压根不是 skill。

三种形态

  1. 带脚本的确定性型（①②③④）——共同结构是：SKILL.md 放决策树，scripts/ 放确定性操作，再挂一个校验脚本当反馈闭环。这类的判据是「它的脚本替我兜住了哪个具体的坑」，不是「它文档写得好不好」。代价是环境依赖：②的校验链要 LibreOffice，④的 OCR 要 tesseract。
  2. 纯流程型（⑥⑦⑧⑨）——一行代码都没有，全是文字与样例。这类的判据是「它的样例是不是我要的那种」。⑦⑨尤其明显地是模板而不是成品：一个装的是别人公司的周报体例，一个装的是别人公司的色卡。
  3. 底层工具（⑩）——它不参与 skill 的触发机制，是被 skill 调用的。把它和①②③④放一张表，只是因为你实际干活时它们总是一起出现。
那个陷阱：①②③④ 和 ⑤ 同名同能力，但是两个东西。⑤ 是 Anthropic 托管的闭源预置版，在 claude.ai / API 上开着；①②③④ 是开源仓库里的同名实现，license 写的是 Proprietary（详见各自 LICENSE.txt），且仓库 README 明写「仅供演示与教学用途」。在 claude.ai 上再手动传一份开源版，等于给同一件事挂两份描述，白交触发冲突的税。

还有一条不属于任何形态

「模板型 skill」这个说法容易被当成一类工具，其实它是个结构：一份决策树 + 一批按需读的 reference + 一个能判对错的校验步骤。①②③④是它在文件格式上的实例，⑦⑨是它在文风上的实例。看懂这个结构，你自己公司那套合同模板、报价单模板，做法完全一样。

// 03

三分钟验货：六条判据，用上面这十个当量尺

论断：办公类 skill 好不好，不用跑，打开 SKILL.md 翻三分钟就知道。上面十个恰好各自示范了一条。
  1. 有没有一个能判对错的校验步骤。②的 validate.py、③的 recalc.py、①的 soffice 转换验证是正面样本。没有校验步骤的文档类 skill，本质是让模型盲写二进制格式——这一类最贵的 bug 就是「文件生成了，但打不开」。
  2. 确定性操作是脚本还是让模型现编。合并 run、重算公式、接受修订这些事，答案唯一、不需要判断力，写成脚本既省 token 又不会跑偏（脚本代码不进上下文，只有输出进）。SKILL.md 里如果全是「你可以这样写代码……」而没有 scripts/，它就是把不该给模型的活给了模型。
  3. 老实交代限制没有。③把「不支持溢出数组函数」「data_only=True 会毁公式」写进正文，是这十个里最能建立信任的一段。一个只讲能做什么、不讲做不到什么的 skill，你得自己去踩它没写的那些坑。
  4. 装的是流程还是别人的偏好。⑥给的是流程，你拿来即用；⑦⑨给的是 Anthropic 自己的体例和色卡，你该 fork 而不是装。分辨方法很简单：读 description，出现「my company」「Anthropic's official」这类词的，都是模板。
  5. 环境依赖有没有写在明处。②③要 LibreOffice 才能转换与重算，④的 OCR 要 tesseract。装之前先确认你跑 agent 的那台机器有这些——这类失败不报「skill 不好用」，报的是一句你看不懂的命令找不到。
  6. 它在你这个环境里到底存不存在。这是办公类独有的一条：同一个能力在 claude.ai、API、Claude Code 上是三条不同的路（预置、skill_id、插件安装），而且不互通——官方文档专门列了一节说自定义 skill 不跨端同步。装之前先问「我在哪儿用」。

// 04

诚实的代价：这类 Skill 的账单长什么样

论断：办公类的 context 税很轻——轻到不值得省。真正的代价在别处：环境、版本、和「装了就以为万事大吉」。

先说轻的那部分

官方文档给的数字很明确：每个 skill 常驻上下文的只有 name 和 description，约 100 token；正文触发时才读，通常 5k token 以内；bundled 文件不读就不花钱（据 platform.claude.com «Agent Skills» 文档，2026-09）。Claude Code 侧还有一条更具体的：所有 skill 描述合起来在 1,536 字符处被截断——注意这意味着装得太多时，排在后面的 skill 描述会被切掉，它就再也触发不了了。这比多花几百 token 严重得多。用 /skill-doctor 看每个 skill 的实际 token 成本与调用频次，想不起用途的就 /plugin 关掉。

再说重的那部分

  • 环境依赖是真门槛。①②③的完整链路要 LibreOffice（soffice），②看效果还要 pdftoppm，④的 OCR 要 tesseract。在一台干净的 CI 机器上，这四件套有一半功能是哑的。
  • API 容器没网、不能装包。⑤跑在 code execution 的沙箱里，无网络访问、不能运行时安装依赖，只能用预装包。你自己写的办公类 skill 要上 API，依赖必须落在那份预装清单内。
  • license 不是 MIT。①②③④的 frontmatter 写的是 license: Proprietary，仓库 README 还有一句「仅供演示与教学用途」。拿去改造进商业产品前先读 LICENSE.txt——这条本系列以后还会遇到很多次。
  • 「装了」不等于「会用」。③的限制清单是最好的例子：你不知道它不支持 XLOOKUP，就会一直纳闷为什么表里是 #NAME?。这类 skill 的学习成本不在安装，在它老实写下来的那半页限制。
  • 触发冲突照旧。①和⑩都能「读 docx」，⑥和⑦都能「写一份文档」。同类能力挂两份描述，模型每次都要挑——这也是别在 claude.ai 上重复传开源版的实际理由。
失败模式：让模型「生成一个季度汇报的 xlsx」，它用 openpyxl 老老实实写了一屏公式，文件也生成了，你打开一看全是 0 或空白——因为 openpyxl 不算值，没人跑 recalc.py。这个 bug 最恶心的地方是：文件能打开、格式也对、只有数是错的，而错得很安静。

// 一页选购卡

先装这三个（Claude Code 场景）：document-skills@anthropic-agent-skills（一条命令拿到 docx/pptx/xlsx/pdf）+ markitdown（pip install 'markitdown[all]'，读的那一半）+ theme-factory（在 example-skills 插件里，十套现成主题，先看 theme-showcase.pdf 再挑）。装完先装 LibreOffice，否则②③的校验链是哑的。

按需再加：doc-coauthoring（要写长文档、且难点在想清楚而不在排版时）· internal-comms（fork 一份换成你公司的体例）· brand-guidelines（当模板读，把 #141413 换成你的主色）· markitdown-mcp（仅当你要让别的 agent 远程转文件）。

明确别装：在 claude.ai 或 API 上再手动传一份开源版四件套（预置的⑤已经开着，重复挂描述只会抢触发）· 在没有 LibreOffice 的机器上指望 pptx 的 validate.py · 原封不动的 brand-guidelines（那是 Anthropic 的色卡，不是你的）。

装完三件事：/skills 看清单 · /skill-doctor 查 token 成本与调用频次 · 记住描述合并后在 1,536 字符处截断，装到触发变迟钝时，先怀疑这条而不是怀疑模型。

// 术语表

OOXML（Office Open XML，办公开放 XML）
.docx / .pptx / .xlsx 的真身：一个 zip 包，里面装着一堆 XML。所谓「编辑文档」就是解包、改 XML、重打包。
progressive disclosure（渐进披露）
skill 分三层加载：name+description 常驻（约 100 token）→ SKILL.md 触发时读 → bundled 文件用到才读。
skill_id
Claude API 里点名预置 skill 的标识，办公类只有四个：pptx / xlsx / docx / pdf，且必须搭 code execution 工具。
recalc（重算）
openpyxl 只把公式文本写进单元格，不计算结果。要靠 LibreOffice 跑一遍才有缓存值，否则别人打开看到的是空的。
merge runs（合并文本片段）
Word 会把一句话切成多个 run 存。不先合并，对 XML 做查找替换就会漏掉被切开的那些。
