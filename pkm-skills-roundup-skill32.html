// WHY THIS MATTERS

会议纪要、收件箱、笔记整理、日程，看起来最该让 AI 代劳，却是整个生态里现成货最不管用的一类。原因不复杂：编码类有客观 oracle（测试绿不绿），办公类有确定性格式（docx 坏没坏），而「这次会议该记什么」只有你知道。所以这张表要分三层读——装错层，就会用 star 数去挑产出型、又拿「像不像我」去要求管道型。

逐条：替你干掉什么 · 什么时候别装

  • makenotion/claude-code-notion-plugin（据仓库页 2026-10 为 491 star）— 本类里唯一的厂商官方产出型：捆了 Knowledge Capture / Meeting Intelligence / Research Documentation / Spec to Implementation 四个 skill，外加 /Notion:search、/Notion:create-page、/Notion:tasks:plan 等十条命令。替你干掉「开会前自己翻五个页面凑背景」。别装：笔记不在 Notion 里。认名字：另有一份 team-attention/notion-skills-for-claude 只有 24 star 且 2025-12-22 已归档，别抄那个。
  • anthropics/skills · internal-comms（官方，Apache-2.0）— 替你干掉「周报 / 公告 / FAQ 每次重新想版式」：examples/ 下四份模板——3p-updates.md（Progress / Plans / Problems）、company-newsletter.md、faq-answers.md、general-comms.md，按类型选一份照着写。这是全表最值得抄的结构：口径留成空槽，你换掉样例就是你的了。别装：你的公司根本不用这几种格式——那就直接 fork 它的目录结构。
  • Claude Code auto memory ＋ CLAUDE.md（官方，零安装）— 替你干掉「每次重新解释你是谁」：auto memory 自己记四类笔记并写进 frontmatter 的 type 字段——user（角色与偏好）/ feedback（你的纠正）/ project（在办的事与决定）/ reference（外部信息在哪）；存在 ~/.claude/projects/<project>/memory/，每次只加载前 200 行或 25KB。官方明写它会跳过「能从代码推出来的」与「CLAUDE.md 已经说过的」。别开的时候：共享机器或演示环境——它是机器本地的明文笔记。关法：autoMemoryEnabled: false 或 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1。
  • basicmachines-co/basic-memory（AGPL-3.0；据仓库页 2026-10 约 4.1k star）— 替你干掉「聊出来的结论随窗口蒸发」：把对话沉成带 frontmatter 的 markdown，正文里用 observation 与 wiki 链接织成知识图，默认落在 ~/basic-memory，另有一份 SQLite 索引供检索。注意 AGPL。别装：你已经有 Obsidian 和一套明确的笔记规范——两套索引会打架（下文 04）。
  • @modelcontextprotocol/server-memory（官方参考实现）— 九个 tool（create_entities / create_relations / add_observations / search_nodes / read_graph …），数据存一个 JSONL 文件，位置由 MEMORY_FILE_PATH 决定。别装：它自称 a basic implementation，单文件、没有项目隔离——当范本读，别当方案用。
  • MarkusPfundstein/mcp-obsidian（MIT；据仓库页 2026-10 约 4.5k star）— 替你干掉「手动翻 vault 再粘贴进对话」：七个 tool（list_files_in_vault / get_file_contents / search / patch_content / append_content / delete_file …）。前置条件：vault 里要先装社区插件 obsidian-local-rest-api。别装：你用 Claude Code 且 vault 就在本机——--add-dir 直接读文件更省一层，也不给它 delete_file。
  • Doist/todoist-mcp（MIT；据仓库页 2026-10 为 554 star）— 替你干掉「读完一段话再手动录三条待办」。值钱的点不是 star 数，是维护主体：Doist 自己维护，不是个人仓库。别装：任务不在 Todoist；或者你的待办其实只需要一个 markdown 清单。
  • nspady/google-calendar-mcp（MIT；据仓库页 2026-10 约 1.2k star）— 十三个 tool，含 get-freebusy、create-events（批量）、manage-accounts（多账号）。替你干掉「三个人对空档」。代价写在它自己 README 里：要你建 Google Cloud 项目、开 Calendar API、配 OAuth 桌面凭据，而且 test mode 的 token 七天过期，等于每周重新授权一次。别装：你只是想看今天几点开会。
  • Readwise 官方 MCP— 替你干掉「划线全躺在 Readwise 里从不复用」：托管在 https://mcp2.readwise.io/mcp，OAuth 授权，工具含 readwise_search_highlights、readwise_list_highlights、readwise_create_highlights 等。别装：不用 Readwise，或者你的阅读笔记本来就同步进了 vault。诚实说清：本站出口策略挡住了 readwise.io 与其文档站，上述命令与 endpoint 取自搜索引擎对 Readwise 官方文档页的两次一致摘要，装前请自行打开该页核对。
  • supermemoryai/apple-mcp（MIT；3.1k star）— 曾覆盖 Messages / Notes / Contacts / Mail / Reminders / Calendar / Maps，是这一类最被推荐的那个。仓库页现在写着：This repository was archived by the owner on Jan 1, 2026. It is now read-only. 列它不是让你装，是让你把「3.1k star 也会被弃养」这件事记进选购判据——尤其因为它要的权限是你半部数字生活。
  • anthropics/skills · skill-creator（官方）— 本类的正解：替你干掉「凭感觉写 skill」。它把流程钉成十一步——澄清意图 → 追问边界 → 写 SKILL.md → 造 2–3 个真实 prompt → 装与不装并行跑 → 写量化断言 → 打分汇总 → 交你评审 → 迭代 → 优化 description 的触发率 → 打包。官方那句话是本期的落点：造能被用一百万次的 skill，而不是只对手头这几个例子有效。别装：你要的东西只跑一次。
两条都踩在名字上。①「Obsidian MCP」在搜索结果里至少有六个同名仓库（含多份 fork），本期点名的是 4.5k star 的 MarkusPfundstein/mcp-obsidian。②「Notion 官方 skills」在 GitHub 上有数个 notion-mcp-server 同名仓库与一份已归档的镜像。聚合站与搜索结果只能用来发现候选，名字一律回 GitHub 仓库目录或厂商官方页面核。
// 02

为什么这三层不能混着比

论断：三层的验收标准完全不同，用一套判据挑必然挑错。
管道层 比什么：覆盖面 · 写操作是否可逆 · 维护主体 · tool 数量 失败模式：接上了但模型选错工具，或者一次 delete_file 删掉你的笔记 能不能装现成的？——能，而且应该。这层没有「你的口径」 记忆层 比什么：存在哪 · 谁能读 · 会不会和你已有笔记争真相源 失败模式：两套索引都半满，你自己也说不清该信哪边 能不能装现成的？——先用官方自带的，不够再加 产出层 比什么：像不像你 —— 没有第二条判据 失败模式：交出一份语法完美、但不是你会写的东西 能不能装现成的？——只能拿它的「结构」，口径必须自己填

混着比的两种典型错法：用 star 数挑产出型（于是装了一份别人公司的周报模板，每次都要改一半，不如不装），和拿「像不像我」去要求管道型（于是得出「MCP 没用」这种结论——它本来只负责把数据搬进来）。

这也解释了 SKILLS.md 给本类定的那句话：最该自建。不是因为现成的质量差，而是产出层的验收标准长在你身上。全表最值得抄的因此是 internal-comms 的结构——一份 SKILL.md 挂四份样例文件，换掉样例就换掉了口径。

// 03

打开 SKILL.md / README 三分钟验货

论断：这一类有六个专属判据，其中第 2 和第 4 条在别的分类里不重要。
  • ① 它读不读你的私有上下文？没有数据入口的「生产力 skill」就是一段 prompt 换了个目录——不如直接贴进对话。先找 README 里有没有 tool 列表或 API 配置。
  • ② 写操作可逆吗？这是本类独有的风险：笔记和日程是破坏性写入面。看有没有只 append 的变体、删除要不要确认。mcp-obsidian 的 delete_file 与 patch_content 就是要盯的两个；日程类要盯 delete-event。能只读就只读。
  • ③ 维护主体是谁？厂商自己维护（Doist/todoist-mcp、makenotion/claude-code-notion-plugin）＞ 高星个人仓库。顺手看最近一次提交、以及仓库顶部有没有归档横幅——本期 apple-mcp 就是这一条的代价。
  • ④ 口径是空槽还是写死的？产出型只看这一条：SKILL.md 底下有没有 examples/ 这类留给你填自己口径的目录。internal-comms 有四份；写死别人口径的，装了也要重写一遍。
  • ⑤ context 税多少？数 tool 个数。google-calendar-mcp 十三个、mcp-obsidian 七个、官方 memory 九个——全开就是三十个工具常驻。更坏的是功能重叠：两个 server 都能「搜笔记」时，模型要先选，选错一次就是一轮空转。
  • ⑥ 隐私半径。它能读到的最大范围是多少？Obsidian 管道给的是一个 vault；Apple 那一类给的是邮件＋短信＋通讯录。按最坏情况算，不按你打算怎么用算。

三分钟怎么分配：一分钟看 tool 列表（①②⑤⑥同时有答案），一分钟看仓库顶部与提交记录（③），一分钟看目录结构里有没有样例槽（④）。

// 04

诚实的代价

论断：本类装得越全，越可能在某天早上发现一半管道断了。

① 弃养，而且是高星弃养

supermemoryai/apple-mcp，3.1k star，2026-01-01 归档只读。那份 Notion skills 的镜像仓库 team-attention/notion-skills-for-claude，2025-12-22 归档。个人维护的集成层依赖的是上游 API 不变，而上游从不保证这件事。所以本类的 star 数比别的分类更不值钱——要看维护主体。

② OAuth 税是真金白银的时间

google-calendar-mcp 要你建 Google Cloud 项目、开 API、配 OAuth 桌面凭据，而且它 README 自己写明 test mode 的 token 七天过期。为了省掉「打开日历看一眼」，你换来每周一次重新授权——算一下再装。

③ 两套索引打架

basic-memory 有自己的 SQLite 索引与 ~/basic-memory 目录，你的 Obsidian vault 有自己的一套。同时跑起来之后，「上周那个决定」会在两边各有半份——真相源必须唯一，要么让 basic-memory 直接指向 vault 目录，要么只留一个。

④ 最大的代价不在工具上：产出层外包不掉。注意官方自己把 auto memory 的边界划在哪——它只记你教过它的（纠正、偏好、决定），明确跳过能从代码推出来的、以及 CLAUDE.md 已经写了的。官方不替你决定「该记什么」。所以如果你期待装一个 skill 之后会议纪要就变成你会写的样子，这个期待在本类注定落空：现成货的收益上限是省掉打开 app 那几步，不是替你判断。
来源：apple-mcp 仓库页归档横幅 · google-calendar-mcp README 的 OAuth 与 7 天 token · Claude Code · memory 文档的 auto memory 四类与跳过规则（均据各页 2026-10）

// 一页选购卡

先装这三个：① /memory 开着，再写一份二十行的 CLAUDE.md——零成本、官方、全项目生效，而且它跳过你已经写进 CLAUDE.md 的东西，两者互补。② 只装你笔记系统对应的那一个管道：Obsidian → uvx mcp-obsidian（先装 obsidian-local-rest-api）；Notion → /plugin install notion-workspace-plugin@notion-plugin-marketplace。③ anthropics/skills · skill-creator——把你这周重复解释过三次的那件事写成一个 skill，这才是本类的正解。

按需再加：Doist/todoist-mcp（待办确实在 Todoist）· Readwise 官方 MCP（有在读的划线）· basicmachines-co/basic-memory（还没有笔记系统时，它可以当那个系统）· anthropics/skills · internal-comms（要周报 / 公告版式时，抄结构换样例）。

明确别装：supermemoryai/apple-mcp（已归档） · @modelcontextprotocol/server-memory（官方自称 basic implementation，当范本读） · basic-memory 与 Obsidian 两套索引并存 · 三个都能「搜笔记」的 server 同时开 · 任何写死了别人口径的产出型模板。

// 术语表

PKM（personal knowledge management）
个人知识管理：笔记、划线、会议记录、日程这一摊私有上下文。
管道层 / 记忆层 / 产出层
本期的分层。管道搬数据、记忆跨会话留存、产出写出成品。三层验收标准不同，不能混着比。
auto memory
Claude Code 自己记的笔记，四类：user / feedback / project / reference。机器本地、按仓库隔离、每次只加载前 200 行或 25KB。
样例槽（examples/）
产出型 SKILL.md 底下留给你填自己口径的目录。有没有这个槽，决定了它是不是「你的」。
context 税
每接一个 server 就常驻一批 tool 定义，占上下文且增加选错工具的概率。
弃养
仓库被归档为只读。个人维护的集成层最常见的死法，与 star 数无关。

// 三个想不通的地方

为什么「最该自建」这句话对本类成立，对编码类就不成立？
差别在有没有客观 oracle。编码类的判据长在仓库外面——测试绿不绿、类型过不过，所以一个陌生人写的 code-reviewer 能直接对你有用。本类的判据长在你脑子里：「这次会议该记什么」「这条划线为什么重要」没有外部仲裁。推论有点扫兴但很实用：本类装现成的，收益上限是省掉打开 app 那几步，想要「替我判断」，只能自己写——这也是为什么 skill-creator 被我放进了选购卡的前三。
官方已经自带 auto memory 了，还需要 basic-memory 这类吗？
看两件事：存在哪、人能不能读。auto memory 存在 ~/.claude/projects/<project>/memory/，按仓库隔离、机器本地（官方明写不跨机器与云端环境），而且只在它觉得值得时才写——它是给模型用的。basic-memory 落成你能用 Obsidian 打开的 markdown，是给人也用的。所以问题不是「哪个更强」，而是你要不要人也读。如果你已经有 vault，答案通常是：别加第二套，把 vault 接上去。
装了一堆管道之后，为什么反而觉得变慢了？
两个机制叠在一起。一是工具数量：日程十三个＋笔记七个＋记忆九个，三十个工具定义常驻，每轮都要读。二是功能重叠——真正费时间的是这个：当 mcp-obsidian 的 search 和 memory 的 search_nodes 同时在场，模型得先决定去哪儿找，选错一次就是一整轮空转，而它不会告诉你刚才选错了。对策很土但有效：同一件事只留一条路，重叠的那个关掉。
